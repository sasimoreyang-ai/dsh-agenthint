# 可靠性合同与迁移

本候选从v0.5.5升级，错误行为更严格：不完整流、不支持的内容、未知缓存变更不再静默继续。参数继承也包括源有效生成设置；切换版本前应检查实际请求参数。

## 控制结果

SessionControlClient返回accepted、failed、unknown或cancelled（附是否派发）。accepted只表示HTTP2xx且响应体正常读取，不是KV completed。超时/网络错误/响应体中断是未知结果；mutation的HTTP408/429/5xx也不证明未执行。

只有resume的明确瞬态HTTP拒绝允许自动重试。pause/compact/stop永不自动重试。一次控制操作固定端点/凭据快照。连接解析也有超时与取消。

## 会话顺序

浏览器输入组件挂载或切换会话时，通过认证 RPC 发送 `activated`（仅 sessionId），不再依赖能否观察到草稿空→非空。`composing` 仍作为补充；恢复持久化草稿不被标为输入事件。两种信号复用既有 ensureResume 幂等逻辑，只处理已知且符合恢复条件的会话，不创建/启动 Agent。卸载会取消后续 RPC。

普通请求在真正进入适配器前取得lease，覆盖prepareCall与stream两种入口，直到模型流完成、错误、取消或迭代器退出才释放。变更操作等待该会话已开始的流；新普通请求等待最新控制队列尾。

默认等待屏障2秒，控制单次超时5秒。预取可以在屏障超时后继续；缓存变更仍在排队/执行或结果未知则新请求抛ControlBarrierError。未知变更在当前bridge中隔离，销毁重开同会话也不能自动清除。

本次保持上述屏障语义；没有把它改成等待引擎 KV 加载完成。会话激活使控制请求有机会更早发出，但实际提前量取决于用户行为，不承诺每次都有预取收益。

明确失败的resume经过1秒冷却可再触发，含屏障已允许数据开始之后才返回的失败。未知预取不盲目重发。后台purpose请求不推进普通状态。实际选定model传给控制，不取目录首项猜测。

## 卸载与恢复

插件lifetime signal取消解析、退避、fetch和排队发送，卸载后不再派发新的控制。已经到达后端的操作不能撤回。请求取消或客户端超时不是后端停止证明。

遇到ControlBarrierError先核对协调器的会话/动作与结果。需要继续工作时使用新会话ID，旧会话另行处理。隔离状态不落盘，不跨插件重载/进程重启或多个DSH实例共享；不要把重启当成未知操作已完成的证据。

## 后端仍需负责

- HTTP接受后的异步KV完成确认。
- 跨实例、重启与迁移后的版本隔离/fencing。
- Hint字段完整转发、会话块登记、实际offload/prefetch/evict与消费。
- KV与memcache正确性，以及固定负载下的质量/性能。

本插件修复客户端顺序和取消，不补造后端事务协议。更换backend要协调窗口、排空并新建会话。
